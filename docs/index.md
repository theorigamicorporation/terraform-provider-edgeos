# EdgeOS Provider

Manage Ubiquiti EdgeRouter configuration (EdgeOS): firewall rule sets, NAT,
port forwards, interfaces and VLANs, DHCP, static routes, WireGuard and system
settings, plus `edgeos_config` for any other config node.

The same provider works with Terraform and OpenTofu under the source address
`theorigamicorporation/edgeos`.

## How it works

The provider talks to the JSON API that the EdgeOS web UI uses. Every change
of one resource is sent as one batch: EdgeOS applies the deletes and sets,
commits them as one transaction and saves the result to `config.boot`. When
EdgeOS rejects a commit nothing changes and the error is shown with the config
path it refers to. Writes are serialised per provider instance because EdgeOS
fails on overlapping commits.

Each resource owns a fixed set of attributes below one config node and does not
touch anything else there. Changes made in the web UI or CLI to managed
attributes are reported as drift and reverted on the next apply.

The login user needs the `admin` level.

## Example Usage

```terraform
terraform {
  required_providers {
    edgeos = {
      source = "theorigamicorporation/edgeos"
    }
  }
}

# Credentials can also come from EDGEOS_HOST, EDGEOS_USERNAME and
# EDGEOS_PASSWORD, which keeps the password out of the configuration.
provider "edgeos" {
  host     = "192.168.1.1"
  username = "admin"
  password = var.edgeos_password

  # EdgeRouters ship with a self-signed certificate. Either trust it
  # explicitly with ca_certificate, or skip verification.
  ca_certificate = file("${path.module}/router.pem")
}

variable "edgeos_password" {
  type      = string
  sensitive = true
}
```

## Authentication

All arguments can also be set through environment variables, which is the
usual way to keep the password out of the configuration:

```sh
export EDGEOS_HOST=192.168.1.1
export EDGEOS_USERNAME=admin
export EDGEOS_PASSWORD='...'
export EDGEOS_INSECURE=true
```

EdgeRouters ship a self-signed certificate. Prefer pinning it with
`ca_certificate` over `insecure = true` when the certificate is valid for the
address you connect to.

## Import

All resources support import, with `terraform import` / `tofu import` or with
`import` blocks. The expected ID is shown on each resource page.

## Compatibility

Developed against EdgeOS 3.0.x on an EdgeRouter X. The web API has been stable
since EdgeOS 1.x, so other EdgeRouter models and EdgeOS 2.0.x are expected to
work. UniFi gateways are not supported.

## Schema

### Optional

- `ca_certificate` (String) PEM encoded certificate to trust for the router, for example the router's own self-signed certificate. Env: `EDGEOS_CA_CERTIFICATE` (PEM text or a path to a file).
- `host` (String) Router address: a host name or IP, optionally with `:port`, or an `https://` URL. Env: `EDGEOS_HOST`.
- `insecure` (Boolean) Skip TLS certificate verification. EdgeRouters ship a self-signed certificate, so this is often needed; prefer `ca_certificate` where you can. Defaults to `false`. Env: `EDGEOS_INSECURE`.
- `password` (String, Sensitive) Login password. Env: `EDGEOS_PASSWORD`.
- `port` (Number) HTTPS port of the web UI. Defaults to `443`. Env: `EDGEOS_PORT`.
- `save` (Boolean) Persist each commit to `/config/config.boot` so it survives a reboot. Defaults to `true`. The `api` transport always saves, so `false` is rejected until a transport that can commit without saving exists. Env: `EDGEOS_SAVE`.
- `timeout` (String) Timeout for each request as a Go duration, such as `30s` or `2m`. Commits of large firewall changes can take a while on small routers. Defaults to `60s`. Env: `EDGEOS_TIMEOUT`.
- `transport` (String) How to talk to the router. Only `api` (the web UI API) is available at the moment; `ssh` is planned. Defaults to `api`. Env: `EDGEOS_TRANSPORT`.
- `username` (String) Login user. It needs the `admin` level to change config. Env: `EDGEOS_USERNAME`.
