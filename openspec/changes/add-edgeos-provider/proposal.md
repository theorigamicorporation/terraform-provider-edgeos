# Add the EdgeOS provider

## Why

EdgeRouters are common in homelabs and small offices, and their config is
usually managed by hand in the web UI or the CLI. There is no maintained
Terraform or OpenTofu provider for EdgeOS, so changes are not reviewable,
repeatable or easy to roll back. EdgeOS has no documented API, which is the main
reason nobody has built one properly.

## What changes

- New provider `theorigamicorporation/edgeos`, usable from Terraform and
  OpenTofu with the same `source` address and the same release assets.
- Transport layer with a small internal interface. The first implementation
  talks to the web UI API that the EdgeOS GUI uses (session login, CSRF token,
  `partial.json` reads, atomic `batch.json` writes). SSH with the Vyatta CLI is
  documented as a second transport for later.
- Writes are serialised per provider instance and applied as one atomic batch
  per resource operation.
- Resources: `edgeos_config` (escape hatch for any path), `edgeos_firewall_name`,
  `edgeos_firewall_rule`, `edgeos_nat_rule`, `edgeos_port_forward`,
  `edgeos_port_forward_settings`, `edgeos_interface_ethernet`,
  `edgeos_interface_vif`, `edgeos_dhcp_shared_network`,
  `edgeos_dhcp_static_mapping`, `edgeos_static_route`,
  `edgeos_static_interface_route`,
  `edgeos_wireguard_interface`, `edgeos_wireguard_peer`, `edgeos_system`.
- Data sources: `edgeos_config`, `edgeos_system_info`.
- A fake EdgeOS API server (in-memory config tree with commit validation and
  fault injection) used by unit and acceptance tests, also runnable locally.
- Repo tooling: justfile, CI on a Terraform and OpenTofu version matrix,
  coverage gate, docs generated by tfplugindocs, goreleaser with GPG signing.

## Non-goals

- Publishing to any registry (done manually by the maintainer).
- The SSH transport in this change.
- EdgeOS features without a resource here (QoS, VPN other than WireGuard,
  zone policies). They stay reachable through `edgeos_config`.

## Impact

New repository, no existing users.
